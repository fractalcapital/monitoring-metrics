# 是否接入 RSI（超卖指标）评估与候选方案

> **状态：已采纳方案 C 并落地（2026-11-27）**。
> **核心结论**：**不需要**将 RSI 做成与 VIX / MOVE / HY OAS 并列的独立核心卡片，也**不建议**纳入「综合情绪压力分」或单独配置飞书 / Bark 报警；已按**方案 C**将标普 500 的 `RSI(14)`、`MA200` 偏离度与 `RV20`（20 日年化实际波动率）内嵌到「标普 500」背景卡，并在 VIX 卡片附带 `RV20 / VRP` 风险溢价条。
> 相关文件：`README.md`、`docs/composite-stress-score.md`、`monitoring/config.py`、`monitoring/series.py`、`scripts/fetch_dashboard.py`、`index.html`。

## 1. 背景与讨论问题

当前仪表盘已覆盖「3 + 2」跨市场波动率与信用风险监控体系（VIX、VIX 期限结构、VVIX、SKEW、MOVE、HY OAS + IG/CCC 信用分层），并附带「标普 500」作为方向交叉验证背景卡与「0–100 综合情绪压力分」。

本次评估的核心问题是：**是否有必要接入 RSI（相对强弱指标，通常指标普 500 的 14 日 Wilder RSI）这类超买 / 超卖指标？如果接入，应该放在什么位置、承担什么角色？**

## 2. 为什么不适合作为核心指标、压力分权重或独立报警

1. **指标本质与项目定位不同**
   - 现有核心指标全部属于**前瞻性 / 结构性的风险定价**（期权隐含波动率 + 信用违约利差），回答的是「跨市场风险压力有多大」。
   - RSI 属于**纯价格回溯的技术面动量指标**，回答的是「短期涨跌是否过头」，天然带有短线择时 / 抄底语义。若将其与 VIX、MOVE、HY OAS 并列展示，会稀释项目“宏观风险监控、非买卖信号”的清晰定位。
2. **不适合纳入「综合情绪压力分」**
   - 参考 `docs/composite-stress-score.md`，综合情绪压力分甚至刻意排除了 SKEW，原因是压力分要求各分量与「当下跨市场压力」保持单调正相关。
   - RSI 具有双向性（高值 = 超买、低值 = 超卖），且 14 日窗口噪声远高于当前 252 个交易日的 1 年分位框架，直接纳入加权会破坏压力分的可解释性与稳定性。
3. **极端行情下容易“钝化”导致报警失真**
   - 在真正的系统性下跌（如 2008 年、2020 年 3 月、2022 年熊市）中，标普 500 的 `RSI(14)` 往往在下跌中段就跌破 30 并在低位反复钝化。
   - 若为 `RSI < 30` 配置飞书 / Bark 报警，既容易制造报警噪音，又可能在风险尚未释放完毕时诱发“已超卖见底”的误判。

## 3. 为什么值得“轻量接入”到标普 500 背景卡

1. **补齐当前缺失的「价格位置 / 超卖」交叉验证维度**
   - 现有卡片衡量的是“恐慌 / 对冲有多贵”，而 `SPX RSI(14)` 补充的是“标的指数短期是否跌过头”，两者结合可读出三类典型场景：
     - **VIX 高位 + 期限结构倒挂 + SPX RSI < 30**：情绪恐慌与价格短期超卖共振。
     - **VIX 平静 + SPX RSI < 30**：温和阴跌 / 无恐慌下跌（只看 VIX 容易忽略）。
     - **VIX 飙升 + SPX RSI 仍在 40 以上**：刚起跌或高位剧震，价格层面尚未进入超卖区。
2. **工程成本极低，零新增数据源与稳定性风险**
   - 后端 `scripts/monitoring/config.py` 已将历史缓存窗口设为 `HISTORY_KEEP = 300`（约 1.2 个交易年），每次运行本来就会拉取约 300 根标普 500 日线（`pairs["spx"]`）。
   - 在 `scripts/monitoring/series.py` 中直接基于现有 `pairs["spx"]` 计算标准 Wilder 口径的 `RSI(14)` 只需十余行纯 Python，**不增加任何外部接口请求、不新增限流 / 断更故障面**。
   - 前端 `index.html` 的标普 500 卡片已有 `区间最高 / 区间最低 / 距区间高点` 统计格与「股指与波动率联动验证」说明块，接入展示非常自然。

## 4. 候选方案对比

| 方案 | 具体做法 | 优点 | 局限 / 取舍 | 适用倾向 |
| --- | --- | --- | --- | --- |
| **A. 不接入** | 维持现有 5 项波动 / 信用指标 + SPX 涨跌与区间背景不变 | 架构最干净，严格聚焦“宏观风险定价”，无技术指标联想 | 缺少直观的短期超买 / 超卖读数，需跳去 TradingView 查看 | 希望定位绝对纯粹 |
| **B. 轻量内嵌 SPX RSI(14)（推荐）** | 仅计算标普 500 的 `RSI(14)`（Wilder 口径），嵌在标普 500 卡片中并给简短状态标签（`<30 短期超卖 / 30–70 中性 / >70 短期超买`）；**不建独立大卡、不进压力分、不单独报警** | 零新数据源、改动极小；看恐慌指标时可顺手确认美股是否短期超卖，且不破坏原有风控逻辑 | 仅覆盖短期（14 日）动量，不反映大盘相对中长期均线的位置 | 想要“恐慌 + 超卖”一眼交叉验证 |
| **C. 补强 SPX 技术背景（RSI + MA200）** | 用现有 300 日 SPX 收盘序列同时计算 `RSI(14)`（短期超买 / 超卖）+ `距 200 日均线偏离度`（中长期牛熊位置），一并放在标普 500 卡片 | 同样零新数据源，兼顾短期超卖与中长期趋势位置 | 标普 500 卡片信息密度上升，技术分析色彩略强 | 既关注短期超卖，也关注大盘中长期位置 |

## 5. 若后续选择方案 B / C 的技术落地草案（仅供参考）

本节仅预留实施口径，**当前尚未决定是否实施**：

1. **计算口径（`scripts/monitoring/series.py`）**
   - `RSI(14)`：采用标准 **Wilder 平滑法**（初始 14 日简单均值 `avg_gain` / `avg_loss`，随后递推 `avg = (prev_avg * 13 + curr) / 14`，`RSI = 100 - 100 / (1 + avg_gain / avg_loss)`），保留 1 位小数。
   - 短样本保护：当回退缓存仅剩少量历史点时（例如不足 30 个交易日，Wilder 递推尚未充分收敛），沿用 `compute_stats` 的保护策略，复用上次有效值或返回 `null`，避免输出失真读数。
   - 若选方案 C：`MA200` 需要至少 200 个交易日收盘价，输出 `ma200` 与 `vs_ma200_pct`（`(close - ma200) / ma200 * 100`）。
2. **数据结构（`data.json`）**
   - 仅作为可选字段挂在 `spx.stats` 下（例如 `rsi_14`、可选 `ma200` / `vs_ma200_pct`），对现有接口消费者完全向后兼容。
3. **前端与推送边界（`index.html`、`scripts/monitoring/alerts.py`）**
   - 仅在 `index.html` 的 `spxCard` 统计格 / 联动验证文案中展示。
   - 不改动 `COMPOSITE_WEIGHTS`、`ALERT_THRESHOLDS` 与飞书 / Bark 报警触发规则；是否附带在手动状态推送的标普 500 一行（如括号附注 `RSI 28.4`）届时再定。
4. **测试覆盖（`tests/`）**
   - 在 `tests/test_fetch_dashboard.py` 补充 Wilder `RSI(14)` 的已知序列基准用例、全涨（100）/ 全跌（0）/ 样本不足降级边界测试。
